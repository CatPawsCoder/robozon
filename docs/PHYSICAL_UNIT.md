# Физический узел: 3-позиционный накопитель-лоток (tilt-tray)

Проектная документация исполнительного узла ПАК. Узел материализует ту же
логику, что и цифровой двойник (`sim/conveyor_sim.py`): принимает товар,
разворачивается на угол зоны и опрокидывает товар в B / C / D. Один и тот же
результат классификации (B/C/D) задаёт одни и те же углы приводов — связка
CV ↔ механика единая для симуляции и железа.

Документ описывает **полноразмерный узел** (под товары до 450×320×320 мм) и
**настольный прототип 1:3** для демонстрации кинематики и управления.

---

## 1. Кинематическая схема

Два вращательных привода на общей раме у конца подающего конвейера:

```
                 ось YAW (вертикальная)
                      │
   лента ──► [ приёмное V-ложе + торцевой флап ] ──► сход в зону
                      │
                 ось TILT (горизонтальная, поперёк схода)

Цикл: ПРИЁМ (yaw=0, tilt=0) → ПОВОРОТ (yaw = уголь зоны) →
      ОПРОКИДЫВАНИЕ (tilt = +DUMP) → ВОЗВРАТ (yaw=0, tilt=0)
```

- **YAW** задаёт направление схода: `B = 0°`, `C = +55°`, `D = −55°`.
- **TILT** наклоняет ложе на угол опрокидывания (≈34°); товар сходит через
  открытый дальний край, флап раскрывается как трамплин.
- Товар **неподвижен в момент поворота** — боковой момент равен нулю,
  крупный товар не перелетает борт (то же проектное решение, что в симуляции).

Углы и последовательность идентичны константам симуляции
(`YAW`, `DUMP_TILT` в `sim/conveyor_sim.py`) — железо и цифровой двойник
управляются одной логикой.

## 2. Расчёт приводов (обоснование выбора)

### 2.1. Полноразмерный узел

Исходные данные:
- масса товара (расчётная / макс.): `m_и = 3 / 5 кг`;
- масса подвижного ложа с бортами: `m_л ≈ 2 кг`;
- плечо центра масс от оси TILT: `d ≈ 0,5 м` (полудлина ложа ~0,45 м);
- время поворота YAW на 55°: `t ≈ 0,5 с`.

**Ось TILT — статический удерживающий момент (худший случай, ложе горизонтально):**

```
M_tilt = (m_и + m_л) · g · d = (5 + 2) · 9,81 · 0,5 ≈ 34,3 Н·м
```

С коэффициентом запаса 1,3 → **привод TILT ≥ 45 Н·м**.

**Ось YAW — динамический момент (разгон поворота):**

```
I ≈ (1/3) · m_общ · L² = (1/3) · 7 · 1,0² ≈ 2,33 кг·м²   (L — длина ложа)
α ≈ 4·θ / t² = 4·0,96 / 0,25 ≈ 15,4 рад/с²                (θ = 55° = 0,96 рад)
M_yaw = I · α + M_трения ≈ 2,33 · 15,4 + запас ≈ 40 Н·м
```

→ **привод YAW ≈ 40 Н·м.**

**Вывод по актуаторам:** оба порядка 40–45 Н·м — это индустриальные приводы:
шаговый двигатель NEMA34 с планетарным редуктором (i ≈ 20–50) либо серводвигатель
переменного тока с редуктором. Хобби-сервы для полноразмера непригодны — расчёт
это показывает явно.

### 2.2. Настольный прототип 1:3 (для демонстрации)

Линейный масштаб 1/3: товар-макет из пенокартона `m_и ≈ 0,1 кг`,
ложе `m_л ≈ 0,15 кг`, плечо `d ≈ 0,17 м`.

```
M_tilt = (0,1 + 0,15) · 9,81 · 0,17 ≈ 0,42 Н·м ≈ 4,3 кг·см
```

**Сервопривод MG996R** (момент ≈ 9–11 кг·см при 6 В) обеспечивает запас ≈ 2,3×
по TILT; для YAW (в основном инерция + трение, нагрузка меньше) — тот же MG996R.
→ **2 × MG996R** достаточно для прототипа.

## 3. Спецификация (BOM) настольного прототипа

| Поз. | Компонент | Кол-во | Назначение |
|---|---|---:|---|
| 1 | Контроллер ESP8266 (NodeMCU) | 1 | приём категории по Wi-Fi/Serial, управление сервами |
| 2 | Сервопривод MG996R | 2 | приводы YAW и TILT |
| 3 | Микросервопривод SG90 | 1 | торцевой флап (лёгкий) |
| 4 | Источник 5–6 В, ≥3 А | 1 | питание сервоприводов (отдельно от USB!) |
| 5 | Пенокартон / ПЛА-печать | — | ложе, борта, желоба, рама |
| 6 | Провода, стяжки, крепёж | — | сборка |
| 7 | Веб-камера / телефон | 1 | вход RGB-D-контура (демо CV) |

**Важно по питанию:** MG996R в пике тянут ~1,5–2,5 А, от USB ESP8266 их питать
нельзя — отдельный БП 5–6 В с **общей землёй** с контроллером.

## 4. Архитектура управления и связка с CV

```
камера → классификатор (Python, classifier/)  ──HTTP POST cat=B|C|D──►  ESP8266
                                                                          │
                                                          Servo YAW · Servo TILT · Servo FLAP
                                                                          │
                                                                    цикл приём→поворот→сброс
```

Контроллер поднимает HTTP-эндпоинт `/sort?cat=B|C|D`; классификатор после
определения категории шлёт запрос — та же величина B/C/D, что уходит в
симуляцию. Прошивка: `hardware/tray_controller/tray_controller.ino`.
Мост «классификатор → ESP» — `hardware/send_category.py`.

Соответствие углов (единое с симуляцией):

| Категория | YAW | TILT |
|---|---:|---:|
| B (подходит) | 0° | опрокидывание |
| C (негабарит) | +55° | опрокидывание |
| D (доупаковка) | −55° | опрокидывание |

---

## 5. Безопасность эксплуатации

- Разделение рабочей и безопасной зон: подвижное ложе огорожено; радиус
  сметания ложа (≈ полудлина) свободен от персонала.
- Аварийная остановка: размыкание питания сервоприводов (реле в цепи 5–6 В)
  переводит узел в безопасное обесточенное состояние.
- Пассивный щелевой отсев микро-габарита (< 10 мм) не требует привода —
  отказоустойчив по построению.
- Ограничение углов приводов программно (`range` в прошивке) и механическими
  упорами — сервопривод не выходит за рабочий сектор.

---

## 6. Порядок сборки прототипа

1. Напечатать/вырезать ложе с V-профилем, борта и два желоба (C/D); собрать раму.
2. Установить MG996R на ось YAW (рама↔поворотная платформа) и на ось TILT
   (платформа↔ложе); SG90 — на торцевой флап.
3. Подключить сервы к ESP8266 (GPIO — см. прошивку), питание — от внешнего БП,
   земли объединить.
4. Прошить `tray_controller.ino`, задать Wi-Fi (или режим точки доступа).
5. Проверить углы командами `/sort?cat=B|C|D`; откалибровать нейтраль и упоры.
6. Запустить классификатор с мостом `send_category.py` — сквозной прогон
   «камера → категория → лоток».

Фото/видео собранного узла размещаются в облачном хранилище; статус —
в разделе «Решение».
