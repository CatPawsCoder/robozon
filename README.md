# Задача 3. Интеллектуальная роботизированная система сортировки товаров

Программно-аппаратный комплекс (ПАК) предварительной сортировки товаров
на участке сортировочного центра: определение категории товара по
формальным правилам постановки и физическая маршрутизация в зону
обработки B / C / D.

**Концепция:** геометрический сортировочный ПАК — детерминированная
классификация по правилам постановки (габариты → «круг в сечении» →
приоритет), цифровой двойник участка, исполнительный узел
«накопитель-лоток» (tilt-tray) с тремя приводами, синхронизация с
конвейером 1 м/с, CSV-метрики и видео полного цикла.

## Быстрый старт

```bash
pip install -r requirements.txt

# 1. Классификация тестового набора (STL -> категории B/C/D)
python -m classifier.run_classification --models data/models --out output

# 2. RGB-D контур: система «видит» товар depth-камерами -> категория (11/11)
python -m perception.rgbd_pipeline
python -m perception.rgbd_pipeline --poses   # устойчивость к ориентации

# 3. Симуляция полного цикла (headless, лог в output/sim_log.csv)
python -m sim.conveyor_sim
python -m sim.conveyor_sim --video           # + видео
python -m sim.conveyor_sim --stress          # стресс-прогон вариаций подачи

# 4. Тесты
pytest tests/ -v
```

Проверено: Python 3.10, Windows 11. Все зависимости — open-source
из перечня допустимого ПО (MuJoCo, trimesh, shapely, SciPy, NumPy).

## 1. Часть определения и классификации товара

Классификация **детерминированная, по формальным правилам постановки**
(не семантическая «бутылка/коробка», а геометрия):

1. **Габариты** (приоритетная проверка): товар должен помещаться в
   допуск основного сортировщика 10×10×10 … 450×320×320 мм.
   Сравнение — поэлементно после сортировки габаритов по убыванию
   (эквивалент «влезает в проём в какой-либо ориентации»).
   Не проходит → **категория C**.
2. **«Круг в сечении»**: если существует сечение, у которого отношение
   радиуса вписанной окружности к радиусу описанной ≥ 0,8 → **категория D**.
3. Иначе → **категория B** (подходит для сортировки).

Реализация метрики круга (см. `classifier/geometry.py`):
- меш выравнивается по осям минимального ориентированного bounding box;
- сечения берутся перпендикулярно трём осям OBB (15 позиций на ось);
- контур сечения = выпуклая оболочка (осознанно: круглое **катится**
  по внешней огибающей; устойчиво к не-watertight STL);
- r_in — pole of inaccessibility (shapely polylabel),
  R_out — минимальная охватывающая окружность (алгоритм Вельцля,
  фиксированный seed → воспроизводимо).

Каждое решение сопровождается PNG решающего сечения
(`output/sections/`): контур + вписанная и описанная окружности +
коэффициент — решение проверяемо, а не декларируется.

Пограничные случаи: коэффициент в зоне 0,8 ± 0,05 помечается
`manual_review_required` — категория назначается по формальному правилу
(отдельной зоны вне B/C/D не вводится), событие логируется для оператора.

### RGB-D контур: система «видит» товар (perception/)

Тот же классификатор работает и по данным виртуальных depth-камер —
замкнут контур **пиксели → категория**:

```
3 depth-камеры (верх + 2 бока 45°) → облако точек → сегментация от ленты
   → фильтр «летающих пикселей» + SOR → габариты + метрика круга
   (аппроксимация эллипса по видимой дуге) → правила B/C/D → команда
```

**Алгоритмика классификации не меняется** — те же правила и метрика, что
для STL; меняется лишь источник геометрии (облако точек вместо меша).
Результат: **11/11 категорий совпадают с эталоном**
(`output/perception/perception_results.csv`), устойчивость к ориентации —
**55/55 измерений** на 5 углах поворота (`--poses`). Каждое измерение
сопровождается depth-кадром и облаком точек (`output/perception/*.png`).

## 2. Исполнительная часть

**Механизм: накопитель-лоток (tilt-tray) на трёх приводах** —
промышленная схема tilt-tray сортеров:

1. **Приём** — лоток с V-образным ложем стоит горизонтально под срезом
   подающего конвейера; товар сходит с ленты через мостик-переходник,
   гасит скорость о встречный склон и оседает в ложбине. Катящийся
   товар (бутылка, тарелка, пуфик) ловит торцевой флап.
2. **Поворот** — сервопривод yaw доворачивает лоток на угол зоны:
   B = 0°, C = +55°, D = −55°. Товар неподвижен в момент поворота —
   исключён перелёт через борт (боковой момент = 0).
3. **Опрокидывание** — сервопривод tilt наклоняет ложе на 34,5°,
   торцевой флап открывается как продолжение склона; товар сходит
   в зону по направляющим юбкам (в кейджи C/D — по каналу юбок).

Ключевые конструктивные решения (все проверены симуляцией):
- **мостик-переходник** закрывает щель лента/лоток — тонкий товар
  (ручка 9 мм) не проваливается; лоток вращается под мостиком;
- **тормозной фартук** на последних 0,4 м ленты гасит вход до ~0,45 м/с;
- **V-ложе + флап** останавливают и качение, и скольжение при приёме;
- **высокие борта** разгонного участка — высокий круглый товар (шлем)
  не скатывается с ленты;
- клиренсы поворота лотка (радиус сметания ~1,2 м) учтены в расстановке
  кейджей и юбок.

## 3. Связка частей (единый контур ПАК)

Симуляция читает `output/classification.csv` — результат части
определения — и превращает категорию в управляющий сигнал приводам:

```
товар в зоне камеры (x = 1,0 м)
  → классификация (бюджет инференса 150 мс)
  → расчёт времени прибытия в лоток: t_eta = t_cam + Δx / v_ленты (1 м/с)
  → ожидание посадки в лоток (контроль по t_eta: нет товара → событие jam)
  → поворот лотка на угол зоны → опрокидывание → контроль входа в зону
```

Синхронизация по времени: скорость ленты известна (1 м/с), команда
приводам формируется заранее; прибытие контролируется по расчётному
времени — задержка сверх резерва фиксируется как затор (`jam_suspected`).

## 4. Результаты симуляции (output/sim_log.csv)

**Маршрутизация: 11/11 корректно. Cycle time: среднее 5,3 с, макс 5,8 с**
(полный цикл: подача → классификация → приём → поворот → опрокидывание →
вход в зону). Микро-габаритная «Ручка» (9 мм) отводится в C пассивным
щелевым отсевом (калиброванная щель 40 мм на мостике) до накопителя —
разбор в отчёте, раздел 5.2.

Тесты: `pytest tests/ -v` — 29 юнит-тестов классификатора (правила,
синтетическая геометрия с аналитическими эталонами, золотой прогон);
`python -m sim.conveyor_sim --stress` — стресс-прогон симуляции
с вариациями подачи (смещение и разворот товара).

Нештатные сценарии (реализованы и логируются в `sim_events.csv`):
- `manual_review_required` — пограничный коэффициент круга;
- `jam_suspected` — товар не прибыл в лоток к расчётному времени;
- `landed_forced` — приём подтверждён по таймауту (ПЛК-логика);
- `dump_boost` — товар завис при опрокидывании → наклон до 38,5°;
- `stuck_or_lost` — товар не достиг зоны → аварийный сигнал;
- `unstable_contact_estop` / `ejected_estop` — аварийный съём с линии.

Полный итоговый отчёт: [docs/REPORT.md](docs/REPORT.md).

## 5. Ограничения и допущения

- Лента моделируется кинематически (тяга + центрирование при контакте
  с полотном, гашение вращения — распределённый контакт реальной ленты);
- зоны C/D — размеченные площадки с ограждением (аналог ролл-кейджей);
  подъём товара в кейдж высотой 800 мм — предмет детализации (наклонный
  жёлоб/подиум);
- для коллизий используются выпуклые оболочки STL (тонкие объекты —
  габаритный бокс); это консервативно для габаритной классификации;
- cycle time ~5 с на товар задаёт темп ~12 товаров/мин на один лоток;
  масштабирование — параллельные лотки или каскад (см. отчёт).

## 6. Параметры проверки (для экспертов)

Управляемые параметры в `sim/conveyor_sim.py`: скорость ленты `BELT_V`,
углы лотка `YAW`/`DUMP_TILT`, бюджет инференса `INFER_TIME`, резерв
затора `JAM_RESERVE`. Сценарий проверки: запустить классификатор → 
запустить симуляцию → сверить `sim_log.csv` (колонки target/actual/correct)
и `classification.csv` с эталоном из раздела 1.
